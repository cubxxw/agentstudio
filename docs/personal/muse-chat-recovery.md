# Muse 后台聊天恢复（GET-482）

2026-11-11 在实际安装的 AgentRoom 复现：Muse 认证成功，连接仍停在“正在连接”；此前聊天显示“结果待核查”，没有远端 taskId。前一轮登录窗口修复不代表后台收发通过。

## 原因与修复

Electron 的 `WebContents.executeJavaScriptInIsolatedWorld` 等待完整导航结束。Muse 的公开控件与聊天 DOM 已可用时，媒体资源仍可能加载，后台驱动的第一次检查因此无法返回，也不能继续轮询恢复。

驱动现在通过 Electron 进程内 debugger 创建命名的独立脚本环境，再执行固定的聊天驱动。网页和驱动的全局状态仍互不可见，没有 Node 能力或跨域通用访问；整个调用有宿主侧五秒截止，超时后不继续后续命令，不自动重发提交。恢复导航也不再阻塞后续健康检查。仅依靠 CDP 的执行时限不足以终止永不结束的 Promise，因此保留宿主截止。

个人服务在尚未就绪时拒绝发送，旧版只有 RPC 错误而没有 taskId，调用方会保守地进入未知状态。现在先保存一个明确失败的任务回执；重复同一 messageId 只读原失败，新消息可在恢复后发送。已开始派发后的错误仍保持未知，不推断未发送。

真实消息还暴露了第二层问题：Muse 先显示临时用户消息 ID，再以正式 ID 替换。正文完全相同、会话位置不变，旧版一次性文本匹配却把第二个 ID 当成手工输入，取消了回复关联。修复记录发送前的会话尾部和本轮回显；仅接受同一位置的精确回显 ID 替换。追加同文消息、不同正文、已经出现助手回复后的新用户轮次或丢失历史锚点，不视为自己的回显。设置页每两秒只读刷新服务状态，防止初始加载状态被永久留在界面上。
