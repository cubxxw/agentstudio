# 从一句话开始的个人工作间

GET-476 · 2026-11-10 · 产品及工程裁决由用户授权 Agent 自主作出。

## 证据与边界

- 目标仓库：`cubxxw/agentstudio`，基线 `b8398111767a415eda97bbd7e2d0ddc65234b31e`。检查了工作协议、架构、API、客户端、连接器、协议、路线图、实际 UI 和测试。原 Electron/Expo + Matrix/Go 桥接没有在本轮运行，不能把静态检查算作运行验收。
- [Raft](https://app.raft.build)：在本人已登录的浏览器只读检查了指定会话及任务抽屉。构建资源 `index-CLnHUMgU.js`，没有暴露可核验 release SHA，不能等同于参考源码 HEAD。私人会话标识和截图仅保留在本机测试目录，不入库。以下只记录机制，不复制私人对话。
- 可见实际行为：使用者询问执行者分工、不同电脑上工具连接的区别；缺失 CLI 时错误提示要求用户修复设备或换运行时；合成阅读安排任务给出文件路径、哈希、已做验证，任务停在复核状态；任务抽屉另有输入框。Agent 关于自身能力的文字陈述不算工具执行证据。
- [AgentStudio 源码](https://github.com/DolphinMiner/agentstudio)：原 API 的 version/idempotency 值得保留；审批记录与投递状态已分开。原 `lib/logic.ts:taskColumn` 把失败归入 done，任务完成语义偏向“草稿已发送”，并不适合所有个人工作。
- [Raft 源码](https://github.com/botiverse/raft-source)仅用于机制研究，精确版本及行号见观察报告。其许可边界下不移植实现。

## 介入分类

| 场景 | 介入性质 | 产品裁决 |
|---|---|---|
| 目标、权衡、对外写入和数据共享范围 | 本人判断 | 给具体对象、预览、账号/执行者和后果；把决定留在当前事情里 |
| 缺少资料或目标不明确 | 信息缺失 | 能先推进的先做，只追问实质影响结果的缺口 |
| 选择 Agent、设备、工具路由、搬运上下文 | 调度负担 | 默认由系统处理；例外时用“缺少什么能力”解释 |
| CLI 不可用、设备离线、额度失败 | 环境约束 | 保留任务、给准确状态和恢复入口，禁止悄悄换提供方 |
| 失联前可能已发生写入 | 结果未知 | 先按稳定操作 ID 查询，不自动重放 |
| 哈希校验通过 | 机器可检验条件 | 仅证明实际字节一致，不能代表内容正确或本人接受 |

## 三个方向，以相同任务比较

统一任务：附两份公开/合成资料，比较并生成报告；需要共享资料或写入第三方时本人决定；离开后回来继续核验。

1. **执行者收件箱**：先选联系人，向其派工，审批另列。复用现有结构最容易，但用户要知道谁拥有哪些账号与上下文，跨执行者复查费力。
2. **一个持续的总会话**：入口最轻，所有事情都在一个时间流里。并发工作、回到旧事和成果版本容易互相挤压，必须增加隐形任务引用和补救交互。
3. **每件事一段对话，结果按需展开**（选定）：输入即开启事情；事情保存消息、执行、决定、成果和证据。执行者作为可解释的路由保留在详情，不要求先学习联系人。回到产品时，待决定和未核验的异常先出现。

选择 3。牺牲：少一个“和某位 Agent 建立长期人格关系”的中心场景，也暂不替代所有人的跨网络 IM 收件箱。收益：同一份上下文和成果有明确归属，适合离开后继续。连续性的基本单位是事情，消息是表达手段，run 是一次执行；会话不等于执行状态。

## 视觉主张：安静、明确、可以停留

主体是中文文字和正在推进的事情。导航退后；强调色用于当前选择/动作，琥珀用于等待本人，绿色状态配合文字说明已核验的具体范围。不用玻璃渐变、密集头像条和每条消息的大卡片。

- `canvas #f8fafb`、`paper #ffffff`、`ink #202932`、`secondary #596671`、`accent #296557`、`attention #8b5c13`。最终对比度按实际截图和浏览器检测校正。
- UI：系统字体 `-apple-system/BlinkMacSystemFont/PingFang SC`。中文正文 16px/1.85；报告 17px/1.95、约 38–42 汉字宽。数字 tabular，代码单独可滚动，链接能回到原始来源。
- 桌面：240px 安静侧栏、主对话 740px；长文独立阅读视图保持底层对话、草稿与位置。窄屏：单列，按需展开列表，阅读全屏。关键决定不依赖悬停或颜色。
- 状态只陈述已知事实，不显示虚假百分比。工具细节收起为执行记录。阅读历史时停止自动滚动，并提供回到最新。
- `prefers-reduced-motion` 关闭非必要过渡；focus-visible、原生 dialog 焦点约束、IME composition、键盘发送均作为验收点。

实际中文报告暴露了 CommonMark 在中文标点旁不识别强调的限制。显示层采用 [CJK Friendly Emphasis 的解析扩展](https://github.com/tats-u/markdown-cjk-friendly/blob/main/packages/remark-cjk-friendly/README.md)，同时支持中文删除线；只影响语法识别，不改写保存的 Markdown、下载字节或哈希。取舍是此处的中文强调规则有意扩展了严格 CommonMark。

参考取舍见视觉研究。核心借鉴分别是 [Linear 的注意力层次](https://linear.app/now/behind-the-latest-design-refresh)、[Things 的渐进展开](https://culturedcode.com/things/features/)、[iA Writer 的文字主体与阅读空间](https://ia.net/writer) 和 [Apple 的排版规范](https://developer.apple.com/design/human-interface-guidelines/typography)。不复制其整套外观。

## 运行和信任模型

新增 `apps/personal`，保留原客户端/Go 服务。一个 loopback Node 22.13+ 进程持久化 SQLite、管理后台队列、提供 UI 和 API；不要求首次对话先启动 Postgres、Synapse 及桥接。Node SQLite 在当前 Node22 中仍为实验接口，已纳入运行要求与验证边界。

默认运行本机已配置的 Codex CLI，不搬运 CLI 登录凭据、不切换提供方；每次只传当前事情、所附资料和明确保存的偏好。内建“本地整理”完成可验证的文本处理，明确不伪装为模型推理。第三方与远端连接在用户填写地址后才可用；远端执行权限自管，不声称提示词具有强制隔离能力。

有可用连接时，协调器可读取目录并准备本地文档或精确的远端动作；目录、来源与返回内容都视为不可信数据。外发仍由当前事情中的具体预览决定，连接可用不是写入许可。MCP 正文保留服务返回的 Markdown，执行记录保留去敏后的原始结构；正文投影不再调用模型，不凭工具成功返回虚构文档或外部效果。

创建、续接、决定和重试使用稳定 clientId；决定使用 version 检查。持久账本区分 queued/running/needs_input/blocked/verifying/completed/failed/cancelled/unknown。完成的报告保留原始 Markdown、时间与 SHA-256，UI 展示 verifiedAt 的实际含义。浏览器关闭不会取消后台进程；本机睡眠/服务停止期间不承诺继续，启动后恢复排队，进行中的外部写入进入未知核查。

运行中补充内容形成持久后续 run，单工作者依次处理。每个 run 的上下文截到自己的 messageId，包含它之前的消息及附件，不允许早先排队的执行读到未来补充。待批准时的新要求取消旧预览并更新版本，替代预览需重新批准。未知远端结果挡住后续队列；已保存补充与“当前执行已经读到”分开表述。取消绑定准确 runId，旧取消请求重放不能停止后来的执行。发送期间继续写的草稿、切换事情的位置，以及请求回包丢失后的原请求正文均需保留。

可选 Bearer 由服务端使用本机工作区 AES-256-GCM 文件 vault 保存；不是 Keychain，也不证明远端账号身份。密文绑定 connectionId、类型、URL 和凭据版本，密钥/记录为 0600、目录 0700。相同 URL 不同 token 是不同连接，公开预览只显示用户输入的标签、认证方式与 `identityVerified:false`；内部凭据引用/版本变化不能沿用旧确认。token 不进入模型目录或返回记录，已知 token 的服务回显先去敏再保存。创建失败不覆盖旧 key/凭据；待核查任务保留连接，安全删除仅删除相应密文并保留 key。缺失/损坏 key 不以新 key 替代，原 key 恢复并重启后才能继续。加密文件不能隔离同系统用户进程，SQLite 也未做整库加密。没有 OAuth、任意认证头或账号证明端点。

记忆由用户明确保存、修改和移除；从新执行起生效。不会把自动推断悄悄升级为长期事实。没有接入和授权的私人项目、其他事情与账号记录不会作为上下文。

## 本轮工作本身暴露的协调负担

源码研究、浏览器、终端和验收账本之间的切换说明，产品应自动保留当前事情、草稿、来源、运行身份与可核查结果，离开再回来时直接呈现未决点。共享主机资源不足时，Agent 可代办有证据的可重建产物核查与恢复，不应把终端排障步骤转交普通用户；不能为继续运行而清掉未完成任务或唯一证据。等待工具返回、CLI 版本检测、服务重新连接与真实本人决定应分别记账。视觉验收也遇到工具脚本写法错误与原生缩放不可用：工具失败和证据缺口应直接标明，不用后续成功冒充首轮通过。这些是亲历观察与设计取舍，不表示当前产品已经实现通用运维代理。

## 验收以证据判断，不自评 95 分

1. 空库直接输入→实际执行→保存可读报告→下载字节哈希一致。
2. 同一请求重发不重复，刷新保留草稿、历史、决定、报告；关闭 UI 后任务继续。
3. 缺失执行器/额度错误如实阻塞；取消后迟到结果不得变成完成。
4. 远端合成服务的决定→送达→执行→核验分开；提交后失联不重复写入，先读取状态。
5. 中文长文、中英混排、引用、表格、代码、安全 Markdown、文件边界可检查。
6. 桌面/窄屏、键盘/IME、历史滚动、错误/离线、空态与大量历史留截图和具体发现。
7. 修改范围的测试、类型检查、构建、独立审查和 CI 分别记录。真实第三方账号、原生安装和部署没有证据就列为未验证。
