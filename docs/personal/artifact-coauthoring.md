# 从群聊到共同作品

AgentRoom 的作品由稳定的 `aw_…` 标识，不依赖某段聊天。原有每条回复保存的 Markdown 成果继续保留；新作品位于独立作品库，有不可变版本、真实贡献记录和普通本地文件。

## 使用流程

1. 建群，加入已发现且可运行的 Codex、Pi。直接讨论文档或静态网页；`@all` 明确请两位回应。每位助手可以通过原生 `creation_propose` 提出自己的分工，而不是在正文伪造工具卡。同一条用户消息形成一张共同方案卡。
2. 讨论结束后审核目标、参与者、模型快照、文件范围、依赖、接收成员和运行上限。可以修改目标、分工、路径和依赖，再审核新版本；也可以暂不制作。批准之前没有作品内容或创作执行。
3. 同意后，现有 `PersonalWorker` 的单个模型执行槽按依赖派工。每位助手在独立工作副本中修改，使用当前文件哈希提交自己的贡献。宿主检查完整候选、CAS 更新 head 并投影本地文件。运行中的模型、提供商和思考配置使用接受时的快照。
4. 额外文件、作品资料或参与者通过权限申请卡决定。申请不会自行授权。等待授权的步骤释放执行槽；同意后恢复保留的工作副本。已有额外资料时，新增参与者需要重新审核完整资料范围。
5. 打开结果卡进入作品库。预览、文件、版本、活动、权限分别显示；人可以编辑文件并保存为人的贡献。接受某个版本、整合完成和发布是不同状态。旧版本恢复为一个新 head，历史记录保留。
6. 共享到另一个群聊，默认固定当前所选版本和当前成员。可以明确选择跟随未来版本或只共享部分路径。第二个群聊提出新的修改方案，仍更新同一个作品 ID。

当前编辑方案会明确申请读取这件作品的全部文件，并把该轮产出的确定版本共享给卡片列出的成员。只读共享可以更窄；审核编辑方案时需要看清这一范围扩展。新成员不自动获得历史版本权限；移除后重新加入也需要重新共享。撤回群共享不会扩大或替代本轮工作授权，停止执行使用结果卡的“停止本轮”。

## 工具和执行边界

讨论工具包括 `artifact_list/read`、`creation_propose/update`、`permission_request` 和 `collaboration_status`。批准后的步骤还可调用 `task_claim/delegate/yield`、`collaboration_message`、`artifact_write/submit/check`、`task_complete`。这是一个统一内核，MCP 和 Pi extension 只适配传输。

Codex 使用每次执行的私有 stdio MCP；Pi 显式加载受信扩展并关闭内建工具及扩展自动发现。两者都关闭继承的无关能力。工具会话凭据只在子进程环境中传递，不进入提示词、argv、卡片或版本文件。内核从服务端运行记录恢复身份，并在调用、缓存返回、派工与整合时重新检查授权。对额外能力不兼容的 CLI，创作模式失败关闭；尚未调用模型的普通聊天可以保留同一后端的原有只读兼容路径。

默认每轮 30 分钟、24 个步骤、200 次工具调用。当前不运行项目脚本、安装依赖、访问任意目录或发布网站。不同 Agent 角色不能冒充不同执行后端。只有用户明确要求时才更改默认模型；已有接受快照不会随全局默认值改变。

停止会撤销会话及授权，只终止本任务拥有的执行器。进程停止未确认、应用中断或工具作用未知时保留 unknown，不能普通重试。失败步骤的已保存贡献和工作副本保留；已经提交的贡献不会重复提交。普通聊天的重试接口拒绝共创运行。

## 文件与恢复

```text
<personal-data>/
├── personal.sqlite                 # 身份、计划、授权、关联、队列、贡献和回执
├── vault/                          # 原有凭据；不导出到作品
├── artifacts/aw_<id>/
│   ├── manifest.json               # 可重建身份与 head 投影
│   ├── current/                    # 普通文件：brief.md、decisions.md、index.html…
│   ├── objects/sha256/<hash>       # 不可变 UTF-8 内容
│   ├── revisions/rev_<id>/manifest.json
│   └── local-backups/              # 物化前旧树和显式保留副本
└── workspaces/stage_<attempt-id>/tree/
```

每个文件最多 1 MiB，作品最多 256 个文件、32 MiB。相对路径、符号链接、共享硬链接和内容哈希都经过检查。必需输入 `brief.md`、`decisions.md` 的指纹包含“当时不存在”；方向改变后，旧贡献不能仅因修改不同文件而自动合并。

Finder 手改 `current/` 会阻止常规覆盖。可把人的本地差异导入为一个贡献，或保留副本后采用新版本，也可用原生目录选择器导出某个确定版本到新目录。并发修改冲突继续阻塞；旧树不会自动删除。预览始终读取确定版本，不读取半写的工作副本。

## 预览与验证状态

静态 HTML/CSS/JS 使用主进程的 `agentroom-artifact:` 专用协议。能力 ID 随机、30 分钟过期，只映射经核验版本中的文件。iframe 没有 preload、同源身份、弹窗、表单、顶层导航、自动下载或外网连接；宿主 CSP 不能被生成页面放宽。

网页在文件/资源检查通过后进入 `waiting_preview`。主进程串行打开独立隐藏的隔离窗口，检查实际页面加载错误、可见内容、原生 bridge 缺失，以及 1280px/390px 的横向溢出。可信结果经私有 utility 消息返回；renderer 和模型没有“上报通过”接口。失败显示部分成果，阻止 completed。这个检查不代表真实后端、全交互、无障碍或生产发布已经验收。文档采用文件完整性检查。

辅助 Web 服务可以使用后端、文件和版本管理，但原生协议预览与原生检查属于 Electron。辅助 Web 不能自行把网站标为原生验收通过。

## 验收入口

构建桌面后运行 `node dev/artifact-coauthoring-acceptance.mjs`。默认使用两个明确标记的合成 CLI、独立 profile 和合成资料，验证原生卡片、调整/拒绝/批准、两位贡献、隔离预览、第二群修改和重开。`--expect-preview-block` 验证真实 Electron 页面错误会阻止交付。`--real` 才使用这台 Mac 配置的实际 Codex/Pi 和模型账号，不替换身份或伪造贡献。用 `AGENTROOM_EVIDENCE_DIR` 选择已注册的验收产物根。

结果和限制见 [2026-11-11 验收记录](artifact-coauthoring-acceptance-2026-11-11.md)。
