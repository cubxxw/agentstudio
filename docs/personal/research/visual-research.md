# AgentStudio 紧凑视觉与交互研究

研究时间：2026-11-10，Asia/Shanghai。范围：官方页面核读、官方画面留证、三种本地结构候选；未改产品代码。以下「观察」是本次可核对的页面事实；「采用」与「建议」是针对 IM personal Agent 的设计推断，尚不代表用户行为数据。

**推荐 A：会话为主，长报告进入专门阅读页，写入决定持续可达。** 日常打开就能交流；任务变长时给结果一个安静位置；离开后靠草稿、阅读锚点与未决事项接续。B 与 C 保留为边界对照：重度研究可逐步获得 B 的按需证据工具，多任务累积后再获得 C 的等待队列。

## 采用什么，放在哪里，牺牲什么

| 采用决定（本次推断） | 具体位置与行为 | 明确牺牲 |
| --- | --- | --- |
| 导航弱、任务强 | 浅暖灰侧栏，正文近白；仅当前会话行有弱底色。主强调色留给当前操作与文字链接。 | 更少的品牌色展示，侧栏扫描速度可能稍降；用位置与清楚的标签补偿。 |
| 稳定工具归属 | 顶栏只回答「在哪个任务 / 有何待决定」；报告的阅读、来源与保存放在报告上下文。 | 顶栏不展示所有能力；少见操作需要展开一次。 |
| 普通回复平排，结果另有位置 | Agent 正文用可读段落，长报告以文档对象呈现；点开进入阅读页，再回原会话。 | 长文多一次打开操作；换来更干净的阅读和稳定的版本对象。 |
| 写入是一个可核对的决定 | 预览准确内容、目标与影响；确认后给持久回执。当前任务决定靠近输入区，跨任务用「待决定」列表。 | 决定占用少量常驻空间；窄屏须收成简短入口，不能一直铺满大卡。 |
| 常用先见，证据按需 | 默认只显示结论、结果与关键状态；来源、比较过程在原位置展开。 | 审计细节不在首屏；必须确保来源一步可达，避免以「简洁」掩盖依据。 |
| 可恢复优先于动态效果 | 返回带一句变化摘要；恢复草稿与阅读锚点；进入 / 退出沿同一路径，支持 Escape 与显式返回。 | 需要维护任务状态与版本，不只是 CSS；动效不能代替这些状态。 |
| 不按工具调用刷屏 | 运行中显示正在完成的阶段与实质变化；完整调用记录放进「过程」。 | 技术用户少了一层实时细节；他们仍可以主动查看。 |

暖灰、绿色和圆角是候选的表达手段，并非由官方资料证明的唯一选择。可以换主题，但不应改变层级与行为。候选不采用全屏玻璃、反复跳动状态或每条消息一个装饰卡片。

## 中文长文的建议字阶

以下数值是 **AgentStudio Web 的起始设计提案**，不是 Apple 的中文排版规定，也不能把 native pt 直接当 CSS px。系统字体首选 `-apple-system / BlinkMacSystemFont / PingFang SC / Microsoft YaHei`；正文不默认等宽字体。

| 角色 | 建议值 | 目的 |
| --- | --- | --- |
| 连续阅读正文 | 17px / 1.85，Regular；桌面内容宽约 680–720px，约 38–42 个汉字 | 给中英文混排和段落留出呼吸；候选 A 实测为 17px / 31.45px。 |
| 报告标题 | 28–30px / 1.4，600 | 建立文档起点；不把每条回复都做成大标题。 |
| 二级标题 | 20–21px / 1.5，600 | 以段前距离形成分组，减少额外框线。 |
| 会话名 / 控件 | 14–15px / 1.5–1.6，500 | 保持导航可扫读，字号不与正文竞争。 |
| 时间 / 次要说明 | 12–13px / 1.6，400–500 | 只能承载辅助内容；权限、错误与写入影响不能降到这一档。 |
| 窄屏正文 | 16–17px / 1.85，左右 20–22px | 自然约 20 字一行，不能强行缩小字号维持多栏。 |

实现建议：正文默认 `letter-spacing: 0`；中文标题不额外紧缩；拉丁大标题的负字距只按语言与实测局部处理。段距约 1–1.15em；小标题前约 1.7em。段落长时通过内容分节解决，不依靠密集加粗。

可访问性约束：正文与必要说明以 4.5:1 作为保守对比目标；高对比偏好下加强必要边界；“待决定 / 进行中 / 失败”同时有文字与形状；焦点清晰。200% 浏览器缩放时改为单列，文本、按钮自动换行。Web 使用 rem、浏览器缩放与响应式布局，不宣称它等同原生 Dynamic Type。减弱动态效果时保留反馈、减少位移。

## 同一任务的三种结构

共同任务：**“比较三份资料，形成报告；涉及写入先让我决定；离开后再回来。”** 三份资料、报告、队列与时间均为明显标注的合成内容；所有按钮最多改写本地演示状态，不调用模型、不写外部应用、不付费。

| 候选 | 主对象 / 布局 | 从请求到回来 | 适配与代价 |
| --- | --- | --- | --- |
| **A 会话为主 · 推荐** | 最近会话侧栏 + 一条主对话；报告按需进入独立阅读页。 | 对话提出请求 → 收到结论与报告 → 预览具体写入 → 暂留或决定 → 回来仍在该会话，草稿与待决定接上。 | 最贴近 IM 习惯，也容纳日常短任务。深度并排核读需要进入来源视图；长文需要多一次打开。 |
| B 文档为主 | 左侧资料 / 大纲，中央报告，右侧围绕正文的对话与决定。 | 从研究工作区接收任务 → 直接核读报告 → 在上下文中决定 → 回到原章节。 | 更适合持续研究与来源比较。三栏侵占小屏；简单问答与生活事务被过度结构化。 |
| C 待办为主 | 左侧状态导航，中间任务队列，右侧结果与决定。 | 请求成为任务 → 完成后进入待决定 → 回来优先处理未决事项 → 再看报告或经过。 | 多任务等待明显、离开后易接续。用户需要管理队列；陪伴感和自然交流被状态结构削弱。 |

**判断理由（推断）：** 目前目标是 IM personal Agent，应先让“找 Agent 说话”成立。A 的常驻结构最轻，能够通过按需报告阅读、来源定位和跨任务待决定列表逐渐加深。若将来数据表明用户多数时间都在编辑报告，可重新评估 B；若同时运行、等待决定的任务成为主要工作，可提高 C 的入口权重。

## 落地需要守住的状态

这部分是设计推断，需主任务结合实际仓库检验。

1. **报告有稳定身份和版本。** 引用指向具体来源片段；回到文档按段落锚点加偏移恢复，内容更新时不能只依赖旧像素位置。
2. **草稿属于会话。** 不随切换任务丢失、不被完成状态清空；来源预览关闭后焦点回到触发处。中文输入法组词中的 Enter 不发送消息。
3. **写入决定绑定内容与目标。** 决定后内容改变，旧决定不能授权新内容；“稍后”保留待办。准备写入、实际写入、成功回执与失败重试是不同状态。
4. **离开不等于取消。** 后台任务若可继续，回来读到真实阶段；若已经停止，应说明停在哪。运行、等待输入、待决定、完成、失败有明确区别。
5. **回执可以再找到。** 保存后标明结果与目标；可撤销的操作提供撤销。不能只给一个短暂 toast 就丢失证据。

| 打开 Apple 官网 → 只抽到 JS 提示 → 读取官方 Markdown → 换正常 HTTPS 请求 | 为得到同一份原文切三次路径 | 对同一可信来源自动尝试正常读取路径，保留来源与抓取时间；只在真正阻塞时说明需要何种输入。 |
| 多个官网逐页读文、找产品截图、滚到支持结论的画面 | “看到什么”与“依据在哪”容易分离 | 任务内自动留存标题、原链接、相关片段与视觉证据；报告中的引用能直接打开对应位置。 |
| 页面导航后重新取 snapshot，再找可点击项 | 工具内部定位状态需要不断更新 | 产品应直接维护任务、文档和来源身份；用户不需要重复告诉 Agent 刚刚在哪。 |
| 官网加载、核读与截图存在数秒等待 | 人只能等，或主动问进度 | 说明当前阶段；有实质变化再通知。未变化时不重复刷状态。 |

## 本地验证与边界

已完成：JS 语法检查；A/B/C 的 1440 × 1000 实际渲染并人工看图；A 阅读页进入与 Escape 返回；A 在 390 × 844 没有页面横向溢出；输入草稿在模拟离开、返回、刷新后仍保留，待决定仍为 1 项。本地保存与撤销只验证演示状态。截图均留在 `output/playwright/`。

本轮窄屏曾发现完整决定卡占用过多阅读高度，已收起说明段、缩短当前决定区，并重新截图。候选用于结构评审，不是无障碍或真实写入验收；尚未覆盖完整焦点陷阱、200% 缩放、屏幕阅读器、真实后台恢复、跨设备同步、产品账户或 provider 成功率。A 的阅读位置仅验证同一页面内返回；没有把刷新后的阅读位置恢复计为通过。

已关闭研究独占的 `get476-design` 浏览器与 127.0.0.1:8876 临时静态服务。资源观测：`dev-storage-guard resources` 初次磁盘 11.31GiB；后续 `df -kP /System/Volumes/Data` 为 11,096,668 KiB 可用，约 10.58GiB。本轮没有安装依赖或启动构建。
